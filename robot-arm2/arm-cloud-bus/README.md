# 云连接 + 总线舵机固件（当前主线）

把机械臂接入云端，实现公网远程控制。**这是最终要用的固件。**

---

## 它是什么

`arm-cloud`（云连接）和 `arm-bus-servo`（总线舵机）的合并版本：

| | 来源 |
|---|---|
| WiFi STA + WebSocket 客户端 + token 鉴权 | `arm-cloud/` |
| STS3215 串行总线驱动 | `arm-bus-servo/` |

```
浏览器 ──HTTP──> Nginx ──> Node 服务器 ──WebSocket──> 本固件 ──TTL总线──> 6 个舵机
```

---

## 和其他固件的区别

| 固件 | 舵机 | 联网方式 |
|---|---|---|
| `arm-bus-servo/` | 总线舵机 | softAP 自建热点（局域网直连） |
| `arm-cloud/` | PCA9685 + 模拟舵机 | STA 主动连出（可公网） |
| **`arm-cloud-bus/`** | **总线舵机** | **STA 主动连出（可公网）** |

前两个是第一代/过渡方案，本固件是最终形态。

## 一、首次配置

### 1. 创建凭据文件

```bash
cd arm-cloud-bus
cp secrets.h.example secrets.h
```

编辑 `secrets.h`：

```c
#define WIFI_SSID       "你的WiFi名称"
#define WIFI_PASSWORD   "你的WiFi密码"
#define SERVER_HOST     "你的服务器IP"       // 局域网测试时填电脑的局域网 IP
#define SERVER_PORT     80                  // ⚠️ 见下方说明
#define ESP32_TOKEN     "和服务器 config.js 里一致"
```

### 2. ⚠️ 端口填 80（如果前面有 Nginx）

| 部署方式 | `SERVER_PORT` |
|---|---|
| 直接连 Node（局域网测试） | `3000` |
| 通过 Nginx（服务器部署） | **`80`** |

### 3. ⚠️ WebSocket 路径是 `/ws`，不是 `/`

固件里已经写好了，这里说明原因：

> Nginx 无法按请求头区分 `location`，而 `/` 要留给静态首页。
> 所以让 ESP32 连到独立的 `/ws` 路径，Nginx 就能按路径分流。
>
> **服务器只校验 token 不校验路径**，所以改路径不需要动后端代码。

### 4. ⚠️ ESP32 只支持 2.4GHz

连不上 5GHz 频段的 WiFi。连不上时先用手机热点试。

## 二、接线

```
                    ┌─────────────────────────┐
                    │     舵机总线（3pin）      │
                    └──┬────┬────┬────┬────┬──┘
                       │    │    │    │    │
                     [舵1] [舵2] [舵3] [舵4] [舵5] [舵6]
                       │
  ESP32 GPIO17 (TX) ───┼─── DATA
  ESP32 GPIO16 (RX) ───┘
  ESP32 GND ─────────────── 电源 GND（共地，必须）
  ESP32 供电 ────────────── 独立 USB（⚠️ 不要和舵机共用）

  6 个舵机 V+ / GND ─────── 5V（或 7.4V）电源，**并联**取电
```

### 三条铁律

1. **必须共地** —— ESP32 的 GND 和舵机电源的 GND 接一起
2. **ESP32 独立供电** —— 舵机峰值电流会把共用电源拉低，导致 ESP32 复位
3. **电源并联，不走串联** —— 串联时第一个舵机的接口要扛全部下游电流，会烧

### 回读（力反馈）需要额外加一个电阻

```
DATA ──[1kΩ]── 3.3V
```

总线是半双工，发完要把 TX 释放成高阻态舵机才能回话。不加也能控制，只是读不到位置和电流。

## 三、烧录与验证

1. Arduino IDE 打开 `arm-cloud-bus.ino`，开发板选 **ESP32S3 Dev Module**
2. 串口监视器（115200）应看到：

```
连接 WiFi: xxx ....
✅ WiFi 已连接
   本机 IP: 192.168.x.x
正在连接服务器 xxx:80 …
✅ 已连上服务器
```

3. **服务器端**应看到：

```
✅ ESP32 认证通过
✅ 这是 ESP32，已登记
```

4. 浏览器打开 `http://<服务器IP>/control`，**登录后**拖动滑块

## 四、出问题对照表

| 现象 | 原因 |
|---|---|
| WiFi 连不上 | 用了 5GHz 频段 / 密码错 |
| 连不上服务器 | IP/端口填错 / 服务器没启动 / 防火墙 |
| 反复「已连上」又「断开」 | **token 不匹配**。以服务器日志为准 |
| 连上了但舵机不动 | 舵机没供电 / ID 没改（出厂全是 1） |
| 6 个舵机同时乱动 | **ID 冲突** —— 必须逐个改成 1~6 |
| 读位置返回 0xFFFF | 缺 1kΩ 上拉电阻 |

> **调试提示**：token 不对时 WebSocket 握手会先成功、服务器随即断开。
> 所以固件串口会看到「已连上」紧接着「断开」反复循环 —— 这不是网络问题。
> **以服务器日志为准**，它会明确打印拒绝原因。

## 五、协议速查

### 关节与舵机编号

| 编号 | 关节 | SO-ARM101 对应 |
|---|---|---|
| 0 | 底座旋转 | shoulder_pan |
| 1 | 肩部 | shoulder_lift |
| 2 | 肘部 | elbow_flex |
| 3 | 腕俯仰 | wrist_flex |
| 4 | 腕旋转 | wrist_roll |
| 5 | 夹爪 | gripper |

### 用到的寄存器

| 地址 | 名称 | 说明 |
|---|---|---|
| 0x28 | Torque Enable | 0=关扭矩，1=开 |
| 0x2A | Goal Position | 目标位置 0–4095（2 字节） |
| 0x2C | Goal Time | 到达目标用时（ms，舵机内部平滑） |
| 0x38 | Present Position | 当前位置（只读，需上拉） |
| 0x3C | Present Load | 当前负载（只读，**力反馈用这个**） |

### 为什么不用软件插补

PCA9685 版需要主循环逐度推进，因为模拟舵机只能"给多少脉宽转多少角度"。

总线舵机可以**把「目标位置 + 到达时间」一起下发**，舵机内部自己按时间平滑走位。

所以本固件**不需要 `stepMotion()`**，一条 `SYNC_WRITE` 让 6 轴同时按各自速度运动 ——
**选对架构，代码反而更简单。**
