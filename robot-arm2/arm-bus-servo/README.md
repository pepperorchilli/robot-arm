# 换成总线舵机（STS3215）

从 MG996R（模拟 PWM）升级到 Feetech STS3215（串行总线闭环），根治 WiFi 射频引起的静止抖动。

---

## 一、为什么要换

**MG996R 的抖动是架构性的，不是接线的锅。**

模拟舵机靠「量脉宽长度」决定角度：脉宽 0.5–2.5ms 对应 0–180°。
ESP32 的 WiFi 射频（2.4GHz）耦合进信号线，脉宽被撑长或削短几个微秒，
舵机就把它当成一次角度变化 → 静止时小幅抽搐。

加电容电阻是**在信号完整性层面压制噪声**，能改善但很难根治。

**STS3215 走数字串口协议**，每条指令带校验和：

```
0xFF 0xFF ID LENGTH INSTRUCTION 参数... 校验和
```

噪声混进来，要么被数字电平阈值（0/1）直接滤掉，要么造成校验失败
—— 舵机**直接丢弃这条指令**，永远不会把噪声翻译成角度。

**这是协议层面的免疫，不是靠滤波压制。** 所以静止时纹丝不动。

## 三、供电改造（最容易踩的坑）

### ⚠️ STS3215 是 7.4V，不是 5V

| | MG996R | STS3215 |
|---|---|---|
| 额定电压 | 4.8–7.2V | **6–8.4V（额定 7.4V）** |
| 静态电流 | ~10mA | ~30mA |
| 堵转电流 | ~1.5A | **~3A** |

**6 个舵机同时动作，峰值电流可达 10A 以上。** 供电必须够粗。

### 两个方案

**方案 A（推荐）：2S 锂电直驱**
买个 2S 锂电池（7.4V），直连舵机总线。最简单，不用降压模块。

**方案 B：现有 12.6V 锂电降压**
```
12.6V 锂电 ──→ 降压模块(12.6V→7.4V, ≥5A) ──→ 舵机总线 V+
```
注意要买**能输出 5A 以上**的模块，普通小模块扛不住。

### 接线粗细

- 供电线 / 地线：**≥20AWG**（越短越粗越好）
- 信号线（DATA）：普通杜邦线即可，电流很小

## 四、接线

```
                    ┌─────────┐
   ESP32-S3         │ 舵机总线 │
                    └────┬────┘
   GPIO17 (TX) ──[1kΩ]───┤  ← 上拉电阻，回读时才需要
   GPIO16 (RX) ──────────┤
   GND         ──────────┤
                         │
   7.4V ─────────────────┤ V+
   GND  ─────────────────┤ GND
                         │
        6 个舵机 DATA 全部并联到这条总线
        6 个舵机 V+ / GND 分别并到 7.4V / GND
```

**要点：**

1. **共地必须做**：ESP32 的 GND 要和舵机电源的 GND 接在一起
2. **只发指令**（位置控制）→ TX 直连即可
3. **要回读**（读角度/力反馈）→ 必须加 **1kΩ 上拉到 3.3V**
   - 总线是半双工的，ESP32 发完要把 TX 释放成高阻态，舵机才能回话
   - 固件里的 `readReg()` 已实现这个逻辑，但硬件上拉不能省
4. 总线总长度尽量控制在 **1 米以内**

## 五、四步验证法（拿到货先做这个）

**别一上来就跑整套。** 按顺序逐个确认，出问题好定位。

### 第 1 步：确认能发现舵机

只接**一个**舵机。烧录固件，打开串口监视器（115200），输入：

```
scan
```

应该看到：

```
扫描总线上 1~10 号…
  ✅ 发现舵机 ID = 1
```

> ❌ 扫不到？检查：波特率是不是 1Mbps、TX/RX 有没有接反、供电是不是 7.4V、有没有共地。

### 第 2 步：确认能转动

```
move 1 90
```

舵机应该平滑转到中位。再试：

```
move 1 0
move 1 180
```

**这一步最重要** —— 如果这里就不抖，说明协议层免疫生效了。

### 第 3 步：改 ID

出厂**所有舵机都是 ID=1**，必须逐个改成 1~5，否则总线冲突。

每次**只接一个舵机**，改完拔下来换下一个：

```
torque 1 0      # 先关扭矩（改 EEPROM 前必须关）
id 1 1          # 第一个：保持不变，跳过
id 1 2          # 第二个：改成 2 号
id 1 3          # 第三个：改成 3 号
id 1 4          # 第四个
id 1 5          # 第五个
```

改完**断电重启**才生效。

> 用 FE-URT-1 调试板的话，图形界面点几下就行，不用敲命令。

### 第 4 步：整套联调

6 个舵机全部接到总线，改好 `SERVO_ID[]` 数组，重启后：

```
center          # 全部回中，观察是否还有抽搐
all 45          # 全部转到 45°
```

**静止状态下观察 30 秒 —— 应该纹丝不动。**

### 第 5 步：开启网页控制

```
w
```

串口会打印热点和网址，浏览器打开即可用滑块控制。

## 七、协议速查

### 包结构

```
[0]   0xFF        帧头
[1]   0xFF        帧头
[2]   ID
[3]   LENGTH = 参数个数 + 2
[4]   指令
[5..] 参数
[末]  校验和 = ~(ID + LENGTH + 指令 + 全部参数) & 0xFF
```

### 用到的指令

| 指令 | 值 | 说明 |
|---|---|---|
| PING | 0x01 | 测试舵机是否在线 |
| READ | 0x02 | 读寄存器 |
| WRITE | 0x03 | 写寄存器 |
| SYNC_WRITE | 0x83 | 广播同步写（多舵机同时到达） |

### 用到的寄存器

| 地址 | 名称 | 说明 |
|---|---|---|
| 0x05 | ID | 舵机 ID（EEPROM，改完需重启） |
| 0x28 | Torque Enable | 0=关扭矩，1=开 |
| 0x2A | Goal Position | 目标位置 0–4095（2 字节） |
| 0x2C | Goal Time | 到达目标用时（ms，硬件平滑） |
| 0x38 | Present Position | 当前位置（只读） |
| 0x3C | Present Load | 当前负载（只读）→ **力反馈用这个** |

### 位置 ↔ 角度

```
0     → 0°
2048  → 180°（机械中位）
4095  → 360°
```

本固件只用了 0–2048 这半个量程（对应 0–180°），预留另一半给需要更大行程的关节。

### 波特率寄存器（0x06）

| 值 | 波特率 |
|---|---|
| 0 | 1,000,000（**出厂默认**） |
| 1 | 500,000 |
| 2 | 250,000 |
| 3 | 128,000 |
| 4 | 115,200 |

## 八、常见问题

| 现象 | 可能原因 |
|---|---|
| `scan` 扫不到任何舵机 | 波特率不对 / TX·RX 接反 / 没共地 / 供电不足 |
| 舵机嗡嗡响但不动 | 电压不够（低于 6V）/ 扭矩没开 |
| 多个舵机同时乱动 | **ID 冲突**（出厂都是 1，必须逐个改） |
| 改 ID 后没反应 | 没断电重启 / 改 ID 前没关扭矩 |
| 读位置返回 0xFFFF | 缺 1kΩ 上拉电阻 |
| 某个舵机偶尔丢指令 | 总线太长 / 线太细 / 供电跌落 |

## 九、力反馈怎么用

拿到力反馈后，可以做的事：

```cpp
uint16_t load = readLoad(夹爪舵机ID);   // 负载 ≈ 力矩

// 夹爪抓握力度控制：抓住物体后，读到的负载会上升
// 检测到负载超过阈值 → 停止闭合 → 实现"抓而不碎"
```

典型应用：
- **夹爪力度控制**：抓鸡蛋不碎、抓铁块不掉
- **碰撞检测**：负载突增说明撞到东西了
- **堵转保护**：负载超限就停机，保护舵机

这是 MG996R 完全做不到的（它只有一根信号线进，什么都不回）。
